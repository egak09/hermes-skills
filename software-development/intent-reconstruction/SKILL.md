# 意图重建协议 (Intent Reconstruction)

> **来源：** 钱学森《工程控制论》第11章（随机输入）+ 第14章（滤波与预测）
> **核心理念：** 在 "低采样率 + 噪声" 条件下，用多假设滤波器重建用户连续意图，避免混叠失真。

## 触发条件（满足任一）

| 触发信号 | 检测方法 |
|---------|---------|
| 短消息 | 长度 < 10 字且无明确指令动词（"做""查""写""跑""改"） |
| 跨话题跳跃 | 语义向量与前轮距离明显（话题突变、无衔接词） |
| 歧义代词 | 含 "它""那个""这个""那边""这样" 且指代不明 |
| 碎片化 | 多条短消息连续发送，意图分散 |

## 协议步骤

### 1. 生成 2-3 个意图假设
基于对话历史 + 当前消息，推理最可能的 2-3 个真实意图。
- 不超过 3 个（超过则用户消息问题更大，直接说明困惑）
- 按概率排序

### 2. 一条消息呈现所有假设 + 各走半步
**关键创新：不额外开一轮确认回合。** 在回复中同时：
- 列出假设
- 每个假设附带第一步动作（"我先…"）
- 用自然语言让用户下一条消息就能消歧

### 3. 不额外追问
永远不要单独发 "你是什么意思？" 或 "请澄清" — 这是浪费一轮交互。

## 输出格式

```
我读出了 {N} 种可能：
A) {假设A} → 我先 {半步动作A}
B) {假设B} → 我先 {半步动作B}
你说的是哪种？（或者都不是）
```

如果确实无法生成合理假设（完全无头绪），改用：
```
这条我抓不太准😅 能多给一点上下文吗？比如你想让我做什么、针对什么文件/项目？
```

## 陷阱与误区

- ❌ 不要只做一个假设然后赌 — 猜错的代价远大于多列一个假设的 cost
- ❌ 不要单独开一轮追问 — "请澄清" 是反模式
- ❌ 假设不超过 3 个 — 更多只说明你真的没读懂
- ✅ 半步动作要真的有用 — 即使猜错了，那个动作本身也推进了某个方向
- ✅ 手机碎片化输入特别容易触发 — 这是用户端的 "低采样率噪声"，别当作用户表达不清

## 示例

用户（手机打字）："那个文件改一下"

```
我读出了两种可能：
A) 上一轮我们讨论的 config.yaml → 我先打开看看当前内容
B) 你最近在改的 src/main.py → 我先读一下最新版本
哪一种？（或者告诉我文件名）
```
