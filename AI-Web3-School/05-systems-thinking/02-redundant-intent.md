# 冗余验证 · 意图重建 · 上下文保鲜

> 三个工程控制论启发的 Agent 设计模式

---

## 1. 冗余验证（Ch17 可靠性）

### 核心理念

**通过冗余（独立第二路径）换取可靠性。**
单点确认不可信——工具返回码不等于实际结果。

### 触发条件

| 操作类型 | 示例 |
|---------|------|
| 不可逆删除 | `rm`, `git reset --hard` |
| 强制推送 | `git push -f` |
| 数据库写 | DROP TABLE, DELETE |
| 影响超出会话 | 修改共享配置、发布到外部 |

### 双路径验证

| 操作 | 独立验证路径 |
|------|------------|
| `write_file` / `patch` | `read_file` 回读关键段落 |
| `git push` | `git ls-remote origin HEAD` 确认远端 SHA |
| 删除文件 | `ls` / `search_files` 确认文件消失 |
| HTTP POST/PUT | 独立 GET 确认资源存在 |

### 推送验证示例

```bash
# 1. 执行前确认
# 高风险操作: git push origin main

# 2. 执行
git push origin main

# 3. 独立验证
git ls-remote origin HEAD | awk '{print $1}'  # 远端 SHA
git rev-parse HEAD                              # 本地 SHA

# 4. 对比
# 预期: 远端 SHA = 本地 SHA
# 实际: abc1234 = abc1234
# 结论: 一致 — 远端已同步
```

## 2. 意图重建（Ch11+14 滤波与预测）

### 核心理念

在"低采样率 + 噪声"（手机碎片化输入）条件下，用多假设滤波器重建用户连续意图。

### 触发信号

| 信号 | 检测 |
|------|------|
| 短消息 | <10 字 + 无明确指令动词 |
| 跨话题跳跃 | 语义突变 |
| 歧义代词 | "它" "那个" "这样" |
| 碎片化 | 多条短消息连续 |

### 三步法

```
1. 生成 2-3 个意图假设（按概率排序）
2. 一条消息呈现所有假设 + 各走半步
3. 不额外追问（浪费一轮交互）
```

### 输出格式

```
我读出了 N 种可能：
A) 假设A → 我先 半步动作A
B) 假设B → 我先 半步动作B
你说的是哪种？（或都不是）
```

### 核心创新

**不额外开一轮确认回合。** 在回复中同时列出假设和半步动作，用户下一条就能消歧。

## 3. 上下文保鲜（Ch9 采样数据系统）

### 核心理念

长对话中早期信息可能已经出了上下文窗口。在依赖早期决策前，主动自检。

### 触发条件

- 对话 > 15 轮
- 即将执行依赖早期上下文的操作

### 三步自检

```
1. 扫描可能已出窗口的决策点
2. 用 3-5 条要点做上下文摘要（不询问用户）
3. 自检："我依据的是当前轮信息还是早期记忆？"
```

### 行为准则

> 这是**内化行为准则**，不是可开关的 skill。
> Agent 应主动维护上下文一致性，不等用户提醒。

## 三模式的统一

| 模式 | 工程控制论 | 核心问题 | 解决方案 |
|------|----------|---------|---------|
| 闭环验证 | Ch7 反馈 | 输出是否正确？ | 对比 + 修正 |
| 冗余验证 | Ch17 可靠性 | 操作是否生效？ | 双路径确认 |
| 意图重建 | Ch11+14 滤波 | 用户什么意思？ | 多假设 + 半步 |
| 上下文保鲜 | Ch9 采样 | 还记得早期信息吗？ | 主动摘要 + 自检 |
