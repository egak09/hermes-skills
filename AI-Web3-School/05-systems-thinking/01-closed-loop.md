# 闭环验证：反馈控制系统的核心

> 灵感来源：钱学森《工程控制论》第 7 章 — 反馈控制系统设计

---

## 1. 核心概念

### 开环 vs 闭环

```
开环（很多 AI Agent 的默认模式）:
  用户指令 → Agent 执行 → 说"完成了"
  没验证结果是否正确

闭环（工程控制论的方法）:
  用户指令 → Agent 执行 → 对比输出 vs 预期 → 修正偏差
  每次闭环都保证质量
```

### 工程控制论的类比

```
r(t) 参考信号（用户需求）
y(t) 输出信号（Agent 产出）
e(t) = r(t) - y(t)  误差信号（偏差）
控制器根据 e(t) 调整 → 使 y(t) 接近 r(t)
```

---

## 2. 五步协议

### 1. 回读输出
用不同于生成路径的方式确认输出内容。

### 2. 逐条对照需求
提取用户原始消息中的**可验证约束**，逐条打勾。

### 3. 标注偏差

| 状态 | 含义 |
|------|------|
| ✅ | 完全满足 |
| ⚠️ | 有偏差但已自修正 |
| ❓ | 无法确定，需用户确认 |

### 4. 自修正或标记
- 能改的立即改 → ⚠️
- 需要用户决策的 → ❓ 说明选项

### 5. 输出验证报告

```
闭环验证:
✅ 需求 A — 已满足
✅ 需求 B — 已满足
⚠️ 需求 C — 偏差说明 → 已自修正
❓ 需求 D — 需要你确认
```

---

## 3. 为什么重要

| 没有闭环验证 | 有闭环验证 |
|-------------|-----------|
| write_file 返回成功 → 以为好了 | read_file 回读确认 |
| 代码生成 → 可能漏边界条件 | 逐条对照需求 |
| "完成了" → 用户发现问题 | 提前自检自修 |
| 信任工具返回码 | 独立验证 |

---

## 4. 陷阱

- 不要跳过验证直接汇报"完成了"
- 不要只验证表面（语法），不验证语义
- 用户说"OK"不等于不需验证（那只是批准执行）
- 验证报告简短嵌入回复末尾即可
- 全部通过时简化为"闭环验证: 全部通过"
