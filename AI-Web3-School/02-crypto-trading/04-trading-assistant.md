# 实战：AI 交易助理

> 用 AI Agent 做交易助理——不接 API，手动报数，AI 负责分析+记录+情绪管理

---

## 1. 为什么不用 API？

```
API 的好处: 自动拉数据、秒级更新
API 的代价: IP 白名单维护、代理 IP 变动导致 -2015 错误、权限管理

手动报数的优势:
  - 零依赖（不需要 API key 有效）
  - 你报的每一笔都是一次自我复盘
  - Agent 只需要链上数据（BlockBeats）+ 逻辑分析
```

---

## 2. 工作流

```
┌─────────────────────────────────────┐
│  开单前                              │
│  用户报: 币种 / 方向 / 理由 / 仓位    │
│  Agent: 查链上数据 + 给出判断         │
│         ↓                           │
│  开单后                              │
│  用户报: 余额更新                     │
│  Agent: 记录到 balance_ledger.md     │
│         ↓                           │
│  平仓后                              │
│  用户报: 盈亏 + 新余额                │
│  Agent: 简明反馈 + 复盘要点           │
└─────────────────────────────────────┘
```

## 3. Agent 的职责

| 职责 | 具体动作 | 数据来源 |
|------|---------|---------|
| 链上验证 | 查 BSC/ETH/Solana Top10 净流入 | BlockBeats API |
| 新闻扫描 | 搜币种相关快讯/文章 | BlockBeats 搜索 |

| 情绪管理 | 止盈提醒 / 贪婪警告 / 复盘 | — |

## 5. 实战学到的教训

### 教训 1: 仓位集中度是第一杀手

```
GENIUS 持仓: 37 U 保证金 / 37 U 余额 = 100% 集中度
→ 任何黑天鹅 = 归零

修复: 止盈一半 → 余额升到 58.1 U，风险分散
```

### 教训 2: 止损是免费保险

```
GENIUS 止损前移到 0.56（入场 0.538）
→ 即使触发，仍然是盈利出场
→ 剩余仓位 = 免费彩票
```

### 教训 3: 妖币的逻辑 ≠ 数据驱动的逻辑

```
BSB: 链上数据为零、新闻为零
但妖币的核心逻辑就是"数据还没反应"
→ 关键不是数据验证，而是止损纪律
```
