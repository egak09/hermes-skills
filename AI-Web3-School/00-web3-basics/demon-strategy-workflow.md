# 受限 Web3 助手实战：妖币合约策略扫描

> 一个真实的 AI × Web3 约束型工作流：AI 负责全市场数据扫描和信号生成，但**不接触私钥、不执行交易、不接触 API 敏感凭证**。
> 所有下单决策和签名操作由人类交易者（Paradigme）完成。

---

## 1. 这个助手要解决什么问题

**问题**：妖币（极小市值 + 高波动山寨币，如 SKYAI / RAVE / FIGHT）市场有超过 200 个候选标的。人工逐币盯盘不可能，但其中存在高盈亏比的短线机会。

**方案**：AI 每 3 分钟自动扫描全市场 K 线数据，通过评分系统（4 种 K 线形态 + OI/Vol 组合 + 技术指标）筛选 ≥68 分的候选信号，加上 **1 K 线方向确认** 过滤假突破。符合条件的信号通过 Telegram 推送给交易者，**交易者自己决定是否开仓并在 Binance 手动下单**。

**核心约束**：

```
AI 可以做：                      AI 不能做：
├─ 拉取市场数据 (Binance API)      ├─ 动用私钥签名交易
├─ K 线形态识别                    ├─ 调用交易下单接口
├─ OI / Volume / 资金费率分析       ├─ 读取或使用 API Secret
├─ 评分 + 候选排序                  ├─ 绕过人工确认自动开仓
├─ 回测验证                        ├─ 修改风控参数
├─ Telegram 推送通知               └─ 替交易者做亏损/盈利决策
└─ 交易记录记账
```

## 2. 完整工作流

```
                    ┌────────────── AI 区 ──────────────┐  ┌── 人工区 ──┐
                    │                                    │  │            │
[Binance API] ──→ scan_market() ──→ 评分 ≥68? ──→ 1K线确认? ──→ Telegram通知
    ↑                                    │ 否        │ 否            │
    │                                    ↓           ↓               ↓
  只读数据                          丢弃信号      丢弃信号      交易者查看
                                                                     │
                                                    ┌────────────────┘
                                                    ↓
                                              🔴 人工决策
                                              ┌─────┴─────┐
                                              │            │
                                           开仓          放弃
                                              │
                                              ↓
                                    🔴 Binance 手动下单
                                    （私钥/API Key 仅人类持有）
                                              │
                                              ↓
                                    持仓管理 · 止损 · 平仓
                                              │
                                              ↓
                                    AI 记录到 balance_ledger.md
```

### 每一步详解

| 步骤 | 谁执行 | 需要什么权限 | 是否受限 |
|------|--------|------------|---------|
| ① 拉取行情数据 | AI（Python 脚本） | Binance 公开 API（只读） | 无需凭证 |
| ② K 线形态识别 | AI（`signals.py`） | 无 | 纯计算 |
| ③ OI/Vol/费率分析 | AI（`signals.py`） | Binance 公开 API | 无需凭证 |
| ④ ≥68 分 + 1K 线确认 | AI（策略逻辑） | 无 | 纯逻辑判断 |
| ⑤ Telegram 推送 | AI（`notify.py`） | Bot Token | Token 在 `.env`，AI 不显式暴露 |
| ⑥ 交易决策 | 🔴 人类（Paradigme） | 自己的判断 | **不可绕过** |
| ⑦ 下单执行 | 🔴 人类（Binance 手动） | 账户私钥 / API Secret | **AI 永不可触** |
| ⑧ 余额记录 | AI（`balance_ledger.md`） | 无 | 人类手动报数 |
| ⑨ 盈亏复盘 | AI（辅助分析） | 公开账本 | 仅供参考 |

## 4. 🔴 人工确认点

整个流程中有 **3 个不可绕过的铁闸**：

| # | 确认点 | 为什么必须人工 | 绕过后果 |
|---|--------|--------------|---------|
| ① | **信号审查** | AI 评分是数学，不是市场判断。可能漏掉宏观利空、项目 Rug 风险、流动性枯竭 | 在错误时机入场，亏损 |
| ② | **下单执行** | 涉及私钥签名和资金转移。API Secret 只能人类持有 | 私钥泄露 = 资产全丢 |
| ③ | **余额上报** | 不接交易所 API（避免 IP 白名单 + -2015 错误），手动报数本身是自我复盘 | 账本失真，风控失效 |

> ⚠️ 原则：**AI 生成的信号是"参考建议"，不是"执行指令"。** 交易者有权在任何时候说"我觉得不对，不跟"。

## 5. 风险与限制

### 风险 1：AI 信号 ≠ 市场真相

```
症状: 评分系统基于历史回测优化，可能过拟合
例子: 68 分阈值在 30 天回测中 0 假信号，但市场结构可能突变
影响: 新的市场环境下可能产生真·假信号
缓解: 人工复核 + 持续跟踪策略表现，不做全自动执行
```

### 风险 2：代理不稳定导致数据盲区

```
症状: GFW 下 Binance API 必须走代理（127.0.0.1:7892）
例子: 代理断连时 scan_market() 返回 0 候选 = 可能错过真实信号
影响: 漏单 / 延迟信号
缓解: 代理监控 + 退路方案（直连备用）
```

### 风险 3：妖币的流动性陷阱

```
症状: 极小市值币种 24h 成交量仅几十万 USD
例子: 推荐仓位看起来合理（2.3% 本金），但实际挂单深度不够
       → 以市价成交时滑点可能达 3-5%
影响: 止损触发时实际成交价远差于预期价
缓解: 仓位限制 + 对低流动性币种降低杠杆（≤2x）
```

### 风险 4：Python 环境分裂

```
症状: MSYS2 git-bash 默认 Python 无 ccxt/numpy/pandas
错误: ModuleNotFoundError: No module named 'ccxt'
修复: 必须用 CPython 314 执行所有脚本
影响: 如果用错 Python 环境，策略脚本直接崩溃
```

### 限制 5：扫描延迟

```
每个币需拉取: K 线 + OI 历史 + 资金费率 ≈ 20 秒
50 个候选币 ≈ 17 分钟
200 个候选币 ≈ 67 分钟
→ 不可能做到"实时全市场"，需缩小范围或用 cron 分批
```

## 6. 如何验证结果

### 验证层级

| 层级 | 方法 | 频率 | 谁做 |
|------|------|------|------|
| 策略回测 | `backtest.py batch N`，30 天历史数据验证信号质量 | 策略调整后 | AI |
| 信号质量 | 对比"AI 推送信号"vs"实际开仓后盈亏" | 每笔交易后 | 人类 + AI |
| 余额核对 | `balance_ledger.md` vs Binance 实际余额 | 每日 | 人类 |
| 盈亏归因 | 区分"策略盈亏"vs"情绪交易盈亏" | 每周 | 人类 |
| 风控红线 | 日亏损 ≥18% → 停止所有交易 | 实时 | 人类执行 |

### 具体验证命令

```bash
# 1. 回测验证（策略调整后）
python backtest.py batch 20

# 2. 单币诊断（信号触发时）
python signals.py test SKYAI/USDT

# 3. 余额账本对比
# AI 读取 balance_ledger.md，人类对比 Binance 实际余额
```

### 最终判断标准

> **链上/交易所实际盈亏是唯一真相来源。**  
> AI 说"这个信号历史上胜率 85%"——不等于"你这次一定能赚钱"。  
> AI 说"总分 110，强烈建议"——不等于"你应该开仓"。  
> 最终只看一件事：**你的账户余额是涨了还是跌了。**

## 7. 架构思维：为什么不"全自动"？

全自动交易 = 私钥/API Secret 交给代码 → 一个 Bug 或恶意依赖就有可能清空账户。这个工作流的设计原则是：

```
AI 权限   = 读数据 + 计算 + 通知（只读）
人类权限 = 签名 + 下单 + 转账（写入）

读/写权限永久分离 ← 这是 Web3 安全的基石
```

即使 AI 系统被完全入侵，攻击者能做的最大破坏是"推送一条假信号"——而假信号在人类复核环节就能被拦截。**系统被设计为"即使 AI 完全失控，也不会导致资金损失"。**
